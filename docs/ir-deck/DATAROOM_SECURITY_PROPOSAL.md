# 데이터룸 보안 개선 제안서 (`DATAROOM_SECURITY_PROPOSAL.md`)

> 본 문서는 검토 지적 **C13** 대응을 위한 **접근 코드 교체 절차** 및 **차기 데이터룸 고도화 제안서**입니다. 실제 비밀값(`IR_ACCESS_PASSCODE`, 토큰)은 본 문서나 저장소에 절대 기록하지 않습니다.

## 1. 접근 코드 즉시 교체 절차 (Cloudflare Worker 시크릿)
기존 접근 코드를 유추 불가능한 16자 이상 고엔트로피 코드로 교체하고, 새 코드는 초대된 투자자에게만 개별 전달합니다.

```bash
# 1) 새 코드 생성 (터미널 출력은 창업자만 확인)
openssl rand -base64 18

# 2) Cloudflare Worker 시크릿 교체 (기존 세션 쿠키도 서명 키/시크릿 변경으로 무효화)
npx wrangler secret put IR_ACCESS_PASSCODE
```

## 2. 이미 적용된 게이트 보안 패치 ([`worker/investorShield.js`](../../worker/investorShield.js))
- `"Google 직원이면 'Google'이라고 입력해 주세요"` 문구 및 `'Google'` 플레이스홀더(KO/EN) 전면 삭제
- 열람자 성함·소속 입력값의 수집 목적(초대 확인 및 열람 기록 한정, 외부 미제공) 명시 고지 추가
- 안내 장수를 실제 22장 데크와 일치시킴 (`tests/api/investorGateWorker.test.ts` 회귀 테스트 검증 완료)

## 3. 차기 데이터룸 보안 고도화 제안 (설계안 — 미구현)
1. **투자자별 개별 접근 코드**: 단일 공용 코드 대신 투자사별 코드 발급(KV 해시 저장) 및 개별 폐기 지원
2. **코드별 만료 기한 (TTL)**: 발급 시 기본 7일/14일 만료일 설정, 기한 경과 시 자동 차단
3. **동적 열람자 워터마크**: 인증 세션의 `label`과 열람 시각을 슬라이드 우측 하단에 반투명 오버레이로 표시해 무단 재배포 억제
